# Intents

**Status:** Live: INT-1..6, INT-9..13 · Draft (Rust rewrite): rest · **Prefix:** INT

## Purpose

What an intent is, where intents live, and every way one enters the loop. Stage 1 (Plan) of
the Claude Code AI-native SDLC playbook: intent is captured once, as a version-controlled file.

## Requirements

| INT-1 | **Intent home:** private repo `intents` (was `gradient-tasks`). One folder per intent, `intents/<id>-<slug>/` with `intent.md` (mine) and `plan.md` (Towercab's, [PIP-28](pipeline.md)); finished folders move to `done/<id>-<slug>/` (`git mv` by `Store::update` when it sets `stage: done\|dropped`; no other folder is moved). `TODO.md` and `DONE.md` are generated by Towercab (**Views** below), never hand-edited. | INT-2 | **`intent.md`** (`Intent::parse`, `src/intents/intent.rs`): front matter = the lines between a first line `---` (a UTF-8 BOM before it is kept) and the next `---` line, a YAML 1.2 mapping (`yaml-rust2`); each top-level key is a `key:` line at column 0, its value on that line or on following lines that are indented or `- ` items; blank and `#` lines stand alone (between a key and its next indented line they belong to the key). Fields: `repo` (string `[A-Za-z0-9._-]+`, not starting with `-`, not `.` or `..`: `is_repo`, also used by `add` and `migrate`; required), `u`, `i` (int 1–5), `a` (int 1–5, optional, [AUT-9](autonomy.md)), `after` (list of ids, INT-3; a single id string counts as one, for `after` only), `model`, `review` (model), `source` (`me`, `issue:<url>`, `alert:<band>`, `review:<pr>,<pr>`): strings; `unlock` (list of globs, [PIP-29](pipeline.md)), `started` (RFC 3339 with offset: `/intent` writes the conversation's start, `towercab add` now, the drafter the issue's `created_at` or the breach time), plus fields Towercab writes (INT-5). Any other key is kept verbatim and never rewritten; a known key with the wrong type, a duplicate key or another column-0 line → can't read (INT-11). Body = everything after the closing `---`, kept as raw text: the first `# ` line is the title (`# Intent: <title>`, the `Intent: ` prefix optional), then `## Problem`, `## Proposed outcome` (bullets; each one is checked by the review, [PIP-5](pipeline.md)), `## Affected users and systems`, `## Constraints`, `## Open questions`. Only `repo` and the title are required; a thin intent runs as written. `towercab add "<repo>: <title>" [uN iN aN]` ([LOOP-15](loop.md)) writes a thin one: `repo`, only the scores given, `source: me`, `started` (now, seconds, local offset), blank line, `# Intent: <title>`; prints `<id> intents/<id>-<slug>/intent.md`. | test_parse_intent, test_thin_intent, test_add_command |
| INT-3 | **ID** = creation time `YYMMDD-HHMM` (local), same-minute clash with any folder in `intents/` or `done/` (readable or not) or an id in `done/legacy.md` → `-2`, `-3`; never reused (`new_id`, `src/intents/id.rs`). Slug from the title at creation, never renamed: lowercase ASCII; `'` and `’` dropped; each run of other characters outside `[a-z0-9]` → one `-`; trimmed of `-`; cut to 48 chars and trimmed again; empty → `intent`; starting with a digit → prefixed `n`. Folder name parse: id `^\d{6}-\d{4}(-\d+)?` (greedy), then `-<slug>`. Commands take any unique ID suffix (`resolve`, over open intents): exact match first, else the one id ending with it; none → `no open intent matches <s>`; several → `<s> matches <n> intents: <ids>`. | test_ids_never_reused, test_suffix_unique, test_slug |
| INT-4 | **Accepted = on `main`.** My commits to `main` are accepted as they are. Every machine-written intent (INT-7, INT-8) is a folder on branch `intent/<id>-<slug>` + PR on `intents`: merge accepts, close rejects. Towercab never picks an intent that isn't on `main`: the store reads only its checkout's `main` working tree, and `Store::open` refuses a checkout on another branch (`intents: <path> is on <branch>, not main`). | test_only_main_is_accepted |
| INT-5 | **Lifecycle**, written by Towercab into the front matter: no `stage` = accepted, not started; `stage:` `design`, `build`, `test`, `deploy`, `maintain`, `done`, `dropped` (playbook stages: `design` = design + spec approval; `build` = plan + build; `test` = verify, proof, publish, CI, verifier; `deploy` = PR review, gate, merge approval, merge, deploy, e2e, release; `maintain` = merged, while a revert ([PIP-19](pipeline.md)) or e2e triage ([PIP-20](pipeline.md)) runs for it; the step is in `status`, [LOOP-13](loop.md)); `waiting: <what I must do>` while it needs me; `pr: <url>`; at `done`: `cost` (float, USD), `agent_time` (int, seconds), `attempts` (int 1–2³²−1) ([MET-10](metrics.md)); `finished` (RFC 3339; the store writes it with `stage: done\|dropped` when absent). Removing `waiting` (or `towercab approve <id>`) continues it ([PIP-17](pipeline.md)); `retry: fresh` starts a new attempt. Written only via `Intent::set(key, Value)` / `remove(key)`, for INT-2/INT-5 fields only (any other key → `<key> is not a Towercab field`, nothing changed): same type checks as parse; a changed key's lines are replaced by one `key: value` line in place, a new key goes last before the closing `---`, both with the opening `---` line's line ending; strings are written plain when `yaml-rust2` reads them back unchanged and hold no control character but tab, else double-quoted (`\"`, `\\`, `\n`, `\r`, `\t` escaped, other control characters as `\xNN`); setting a key to its current value changes nothing; ints in decimal, floats with 2 decimals, lists in flow style `[a, b]`. | test_lifecycle_fields, test_done_moves_folder |
| INT-6 | **Generated views** (`src/intents/views.rs`), rewritten on every Towercab write, layout in **Views**: `TODO.md` = Waiting on me (with the action), In flight (stage), Next (priority order, [PRI-4](priority.md), `src/priority.rs`), Parked (`priority < [intents].cutoff`, default 7), Can't read (INT-11); `DONE.md` = newest first: date, id, repo, title, PR, cost, agent time, attempts; then `done/legacy.md` verbatim. | test_todo_view, test_done_view |

The code PR says `Closes <issue>`; a rejected intent comments "not accepted" on the issue. | test_issue_draft, test_issue_linked_once, test_issue_closed_by_pr |

| INT-10 | Towercab pulls before reading and commits + pushes each write straight to `main`; on conflict it rebases and retries, never overwrites my edits. Parse → write of an untouched file is byte-identical; a changed file keeps every line it didn't change. Protocol (`src/intents/git.rs`, the `git` CLI with `-c user.name=towercab -c user.email=towercab@localhost -c commit.gpgsign=false`, `GIT_TERMINAL_PROMPT=0`): uncommitted changes in the checkout → refuse; read = `git pull --rebase --quiet origin main`; write = pull, apply the change, regenerate both views, `git add -A`, commit `towercab: <what> <id>`, `git push --quiet origin HEAD:main`; a failed push → `git fetch origin main`, `git reset --hard origin/main`, re-read, re-apply the same change, commit, push again; at most 3 retries, then `git reset --hard origin/main` and `push failed 4 times: <stderr>`. Nothing changed → no commit. No `origin` remote → commit locally only. | test_concurrent_edits_both_kept, test_round_trip_is_byte_identical, test_changed_file_keeps_other_lines, test_push_retries |
| INT-11 | A file that doesn't parse is never picked or rewritten; it is listed under "Can't read" in `TODO.md` with the reason (`<path>: <reason>`, e.g. `intents/<dir>/intent.md: u must be an integer 1-5`); `get`/`update` on its id fail with that reason; other writes leave its bytes untouched. | INT-13 | `towercab migrate`: each `TODO.md` line (`- [ \|~\|!\|x] [<id>] [uN iN aN] <repo>: <title> [after:<ids>] [@model] [review:<model>]` + `  <key>: <value>` lines) (+ its `tasks/<id>.md`) becomes `intents/<id>-<slug>/intent.md` with the same ID (none → new, INT-3), the scores written on the line, `after`, `model`, `review`, `pr`, `retry`, `note` → `waiting` (`[!]` / `[~]` without a note → `waiting: was [!] before migrate` / `was running before migrate`), `source: me`; `done when` → a `## Proposed outcome` bullet; other keys as `- <key>: <value>` and `tasks/<id>.md` (then `git rm`) → `## Notes`; `[x]` → `done/` with `stage: done` (no `finished`: `DONE.md` shows the ID's date). `DONE.md` lines (minus the title, comments and blank lines; none from a generated `DONE.md`) move unchanged to `done/legacy.md`, shown at the end of the generated `DONE.md`. Rows within a section: [PRI-4](priority.md) order (Can't read: by path), missing `u`/`i` shown as 3. Waiting = has `waiting`; In flight = `stage` set, no `waiting`; Next/Parked = neither. `stage: done` or `dropped` → `DONE.md` only, wherever the folder is. `<pr>` = `[<repo>#<n>](<url>)` for `https://github.com/<owner>/<repo>/pull/<n>`, else the value. Unfinished = not in `done/`, not `stage: done` or `dropped`, not in `done/legacy.md`. Date = `finished`'s date, else the ID's; sorted by date, then id, both descending. Agent time = `<m>m<ss>s` under an hour, else `<h>h<mm>m`. "Generated" (INT-13) = a line starting `<!-- generated by towercab`.

## Out of scope

- Other stores (Notion, Jira). The playbook's "linkage as the minimum bar": an issue and its intent link to each other; `intent.md` is the source of truth.
- Issues from repos not in `[repos]`.

## Decisions

- Intent, not task (my call): the playbook's word; it starts as intent and carries through to the PR.
- One file per intent, merge = accept (my call): what I write is accepted on commit; whatever a machine
  writes waits for my merge, so nothing agent-written runs unseen.
- Only issues labelled `intent` (my call): a label is a deliberate act; other issues stay mine.
- Agents propose `u`/`i`, I adjust before merging; they never propose `a`; a worker may only lower it ([AUT-7](autonomy.md)).
- Separate repo, not a folder in each product repo: intents span repos (the playbook allows a dedicated home for that).
- Generated `TODO.md`/`DONE.md`: one place to read on the phone; the files are the source of truth. Ids link to their folders.
- Timestamp IDs: sort by age for free; minute precision is enough for one person.
- Front matter edited by line, never re-serialised: a YAML library reads the values, writes replace only the changed key's lines, so my comments, order and quoting survive.
- Rebase = replay: on a rejected push Towercab redoes its change on the fresh `main` instead of `git rebase`, so the generated views never conflict and always reflect the latest files.
- `finished` added to INT-5: `DONE.md` needs a date; a `git log` per folder on every write is slow.
- Slug fixed at creation, `n` before a leading digit: links stay valid, and `<id>-<slug>` parses one way.
- `[intents]` config ([LOOP-1](loop.md)) falls back to `[tasks]`: the Python version reads `[tasks]` from the same `config.toml` until the switch-over.
- INT-13 changed from "refuses if `intents/` exists": `intents/` already holds the hand-written Rust intents, so that guard would block the one run; the generated marker in `TODO.md` is the guard now. Old `DONE.md` lines live in `done/legacy.md` because `DONE.md` is regenerated.
- Store writes refuse before `migrate`: regenerating `TODO.md` would wipe the line format the Python Towercab still reads.
- Built: `migrate` also refuses an existing `done/legacy.md`, an ID on two lines and an indented non-`key: value` line (nothing dropped or appended twice); `[x]` gets no `finished` (the real date is unknown). A blank or `#` line inside a key's indented block belongs to that key, so such YAML lists stay readable and replaceable.
- `migrate` is verified on fixtures (`test_migrate`); the real run is mine after merge, at the switch-over (the intent's open question).
- INT-5's "continues" and "`maintain` during a revert" are verified where they are built: [PIP-17](pipeline.md) `test_continue_by_waiting`, [PIP-19](pipeline.md) `test_revert_flow`. The store builds the fields.
- Crates: `clap` (derive), `toml` (read as a table, so errors name the key; no `serde` derive needed), `yaml-rust2` (`serde_yaml` is archived; default features off), `chrono`, `regex`; dev `tempfile`. Git through the `git` CLI, not libgit2: no C build, my shell's auth ([LOOP-19](loop.md) swaps in the App token and identity later).
- CLI now: `add`, `migrate`, `--version` (Cargo version `0.3.0`, after the Python `0.2.0`); the loop intent adds the rest of [LOOP-15](loop.md).
